介護報酬請求の点検自動化の進め方フロー

請求ソフトの出力と介護記録を、毎月の請求前に機械が先に突き合わせます。事務責任者は、出てきた候補の一覧を見て請求を確定します。その状態までの道のりを、6つの段階に分けました。

請求の確定事務
責任者

誰が何を受け持つか

点検を3つの仕事に分けます。日付や回数の照合は決まった規則で動く仕組みに、文章で書かれた記録の読み取りは Claude に、請求の確定は人に割り当てます。

規則による突き合わせ

数と日付を照合する

  • 利用日数・回数・時間区分の照合
  • 認定の有効期間、要介護度と請求コードの照合
  • 加算の算定日と職員の勤務実績の照合

同じデータを入れれば、毎回同じ結果が出ます。

Claude

記録を読み、理由を書く

  • 自由記述の記録から「入浴した」「訓練を行った」「居宅を訪問した」に当たる記述を日付つきで抜き出す
  • 候補ごとに、なぜ候補なのかと根拠の箇所を文章にする

算定できるかどうかの結論は出させません。

事務責任者・管理者

決めて、確定する

  • 候補を採用するか見送るかの判断
  • 記録の補完と請求内容の修正
  • 請求ソフトでの確定と伝送
  • 解釈に迷う要件の判断(必要なら指定権者へ照会)

この業務が難しい理由は3つあります。請求ソフトからデータを取り出せるか、算定要件を点検の規則に書き起こせるか、利用者の情報を安全に扱えるか、です。2026年11月22日付の業務トリアージで実装難易度を4(5段階)としたのもこの3点によります。先に着手するなら、最初の4週間でこの3点を順に確かめます。

進め方 6つの段階

請求は月に1回なので、本番で確かめられるのも月に1回です。そこで、請求が済んだ過去の月で先に試し、その後に当月の請求で従来の点検と並走させます。期間は目安で、最初の聞き取りの後に確定します。

  • できあがるものその段階の成果物
  • 次へ進む条件人が確かめてから進む
  1. STEP0
    第1週

    現状を確かめる

    • 下の「最初の1週間で確かめる7項目」を事務責任者と管理者に聞く
    • 請求ソフトから、実際に1か月分の請求明細と提供実績を出力してみる
    • 請求ソフトに点検の機能があれば、そこで足りる項目は自動化の対象から外す
    • いまの点検にかかっている時間と、返戻・過誤の件数を記録しておく(後で比べる基準になる)
    できあがるもの

    現状のメモ、データの所在の一覧、いまの点検時間と返戻件数

    次へ進む条件

    請求明細と提供実績を「利用者ごと・日ごと」の単位で取り出せる。取り出せない場合はソフトの提供元に出力方法を確認する。帳票の PDF から読み取る方法は、精度も手間も落ちるので最後の手段にする。

  2. STEP1
    第2〜3週

    点検ルールの台帳を作る

    • 届け出ている加算ごとに「算定要件 → 必要な証跡 → どのデータのどの項目で確かめるか」を1行ずつ書く
    • 最初は10〜15行に絞る。過去の返戻の理由と、金額の大きい加算から選ぶ
    • 各行に、根拠となる告示・通知の該当箇所を書き添える
    できあがるもの

    点検ルール台帳の初版(事務責任者と管理者が内容を承認したもの)

    次へ進む条件

    すべての行に根拠を書けている。根拠を書けない規則は台帳に入れない。

  3. STEP2
    第3〜4週

    データを整える

    • 対象は1拠点、請求が済んだ過去2か月分に絞る
    • 氏名・被保険者番号・住所を、事業所内だけで通じる利用者番号に置き換える
    • 紙の記録は、試す間は点検に使う項目(入浴・訓練・提供時間など)だけを表に入力する
    • 計画書の作成日と同意日、職員の勤務実績と資格、認定の有効期間をそろえる
    できあがるもの

    突き合わせ用のデータ一式、置き換えの対応表(事業所内だけで保管)

    次へ進む条件

    置き換え後のデータに氏名や番号が残っていないことを、人の目で確かめた。

  4. STEP3
    第5〜6週

    過去の月で試す

    • 請求が済んだ月に仕組みを当て、当時人が見つけた点、実際に返戻になった点と比べる
    • 数えるのは3つ。出てきた候補の件数、そのうち正しかった件数、人は見つけたのに仕組みが出さなかった件数
    • 的外れな候補が多い規則は条件を絞り、見逃しがあった規則は台帳に行を足す
    できあがるもの

    試行の結果表、直した台帳の第2版

    次へ進む条件

    見逃しの原因を説明できる。候補の量が、事務責任者が1回で目を通しきれる範囲に収まっている。

  5. STEP4
    2〜3か月目

    当月の請求で並走する

    • 従来の点検はやめずに続け、自動点検の一覧を横に並べて見比べる
    • 請求の後に届く返戻・過誤の結果を台帳に戻し、規則を直す
    • 毎月の請求の日程に、出力と点検の日を組み込む(下の「毎月の流れ」)
    できあがるもの

    2回分の並走の記録、毎月の手順書

    次へ進む条件

    2回続けて、人の点検で見つかった点を自動点検も出せている。

  6. STEP5
    4か月目以降

    本運用に移し、拠点を広げる

    • 人の点検を「一覧の確認」に切り替える
    • 拠点は1つずつ増やす。事業承継で加わった拠点は、記録の様式を先にそろえる
    • 報酬改定と、加算の届け出を変えたときに台帳を直す担当者を決める
    できあがるもの

    全拠点で使う台帳と手順書、台帳の更新担当

    続ける条件

    点検時間と返戻件数を STEP 0 の記録と毎月比べ、悪くなった月は原因を台帳に書く。

規則 と Claude の両方

最初の1週間で確かめる7項目

STEP 0 で事務責任者と管理者に聞く内容です。1 と 2 の答えで、仕組みの作り方が決まります。

  1. 請求ソフトの名前と、請求明細・提供実績を CSV などのデータで出力できるか
  2. 介護記録はどこにあるか(紙、Excel、記録ソフト)。拠点によって違うか
  3. いま届け出ている加算の一覧(体制届の控え)
  4. 過去1年の返戻・過誤の件数と理由、運営指導で受けた指摘
  5. いまの点検は、誰が、毎月何日に、何時間かけて、何を見ているか
  6. 利用者の情報を外部の AI サービスで扱うことについての社内規程と、利用者への説明の範囲
  7. 最初に試す拠点はどこか。請求が済んだ過去2か月分のデータを出せるか

利用者情報の扱いと、測るもの

利用者情報の扱い

  • 介護記録は、病歴など特に配慮が要る個人情報を含む。AI に渡す前に、氏名・被保険者番号・住所を利用者番号に置き換える
  • 入力した内容が AI の学習に使われない契約と設定のサービスを使う
  • 事業所の個人情報の規程と、利用者に説明している利用目的の範囲に収まるかを確かめる。収まらなければ規程を先に直す
  • 確認には、厚生労働省の「医療・介護関係事業者における個人情報の適切な取扱いのためのガイダンス」を使う
  • 点検の一覧も、請求書類と同じ扱いで保管する

毎月測るもの

  • 点検にかかった時間
  • 算定漏れの候補のうち、実際に請求へ反映した件数
  • 返戻・過誤の件数
  • 的外れだった候補の割合

効果の大きさは、試す前には分かりません。STEP 0 で記録した値と、STEP 3 以降の実測を比べて判断します。

  • この資料は、貴社の公開情報と通所介護の一般的な業務の流れをもとにした進め方の案です。貴社の実際の業務とは違う点がありえます。
  • 加算の名称と要件の例は一般的な知識にもとづくもので、個別の算定可否を示すものではありません。台帳を作る段階で、現行の告示・通知と指定権者の解釈を確かめます。
  • 期間と日付は目安です。請求ソフトと記録の状況を聞き取った後に確定します。
